# 复用语义一致的埋点字段，新增前确认

规则描述：修改埋点前先查看现有事件、字段及其含义，优先复用能够准确表达当前行为的字段。新增埋点字段前必须与用户确认。现有字段语义有歧义或不能准确表达需求时，不强行复用；向用户说明差异，确认使用哪个字段或是否新增字段。适用于埋点事件的字段设计与修改。

以下示例中，现有 `document_save` 事件的 `entry` 表示操作入口，`source` 表示文档来源；用户只要求记录工具栏触发的保存。

不好的写法：自行新增重试字段，或把操作入口塞进代表文档来源的字段。

```ts
track('document_save', {
    entry: 'toolbar',
    is_retry: retryCount > 0, // 未确认的新字段
});

track('document_save', { source: 'toolbar' }); // 语义不符
```

喜欢的写法：复用语义匹配的已有字段；若还要记录重试次数，先说明现有字段无法表达并向用户确认。

```ts
track('document_save', { entry: 'toolbar' });
```
